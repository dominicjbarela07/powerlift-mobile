# Strength Ledger Mobile Release Law

Read the parent project's `AGENTS.md` and governing architecture before work.
TestFlight is cumulative. No asset, catalog record, route, preference, control,
behavior, animation, audio, history, or approved visual system may disappear or
revert without exact explicit owner authorization. DEV absence and Git history
are not authorization. Fallback rendering can conceal an actual product loss.

Use `scripts/publish-validated-ios-ota.mjs` for OTA publication and the governed
native build wrapper. Run `scripts/testflight-cumulative-integrity.mjs` against
the source and fresh export. Missing protected state, unauthorized negative
deltas, unknown classifications, and missing/stale user-visible runtime proof
block publication. Preserve current, previous, and historical protected baselines.

Do not bypass, weaken, quarantine, or regenerate these gates to obtain a pass.
Direct EAS publication that skips the cumulative gate is forbidden. The Oct 2
2026 asset-loss incident must remain an executable regression: missing the
TestFlight artwork export switch must fail before bundling; an export omitting
previously valid approved assets must fail before publication.

Restore from exact prior valid implementations while preserving newer valid
work. Back-propagate every release restoration to canonical DEV in the same run.
Ask the owner only for genuine conflicting product choices. Never claim a
physical-device fix from synthetic tests. Never use "workout" in product copy.
Production Mobile 2.0.2 is protected and is not a publication target here.
