`resolveApprovedExactMovementArtwork` / `hasApprovedExactMovementArtwork` in
`lib/movement-artwork-hero.ts` require all of:

1. DEV runtime and the existing canonical effective/performed identity resolver.
2. Exact governed MovementDefinition ID, stable artwork key and compatible taxonomy.
3. A positive human receipt in `artwork-review/runtime-policy.json`; no active denial.
4. Approval of the currently mapped candidate's exact bytes, verified by the startup guard.

The backend derives `approved_exact_artwork` entries containing `key`,
`movement_definition_id`, `candidate_id`, and `app_sha256`. Durable prior user approval or
an authenticated human UI decision bound to the candidate hash and decision history is
required. Automation success cannot grant eligibility. Approving a regenerated candidate
does not make it the active mapping: governed promotion is still required. Reopening or
rejecting the mapped candidate removes its positive receipt immediately in the exported policy.

Identity labels, file existence, pending preservation exceptions and focal metadata never
grant eligibility. Performed/effective identity takes precedence over programmed identity;
conflicts or missing governed identity fail closed through the existing resolver.

## Presentation ownership

`MovementArtworkHero` is one memoized presentation layer shared by the ordinary active
Logger, the currently selected active superset member, and the explicitly marked DEV crop
study. The first two callers resolve approval before mounting it. Upcoming/completed
members remain compact. An exact hero suppresses the duplicate small image; missing
approval retains compact regional identity. The new approval requirement on Logger
thumbnails does not globally remove the grandfathered DEV previews from other consumers.

The layer is absolutely positioned inside the existing header footprint. A bounded square
image is placed around a center-right focal target, with horizontal text protection and
vertical edge falloff matching the black or selected superset surface. It adds no image
panel or minimum header height. Existing prescription typography, physical equipment,
plate stack, History, rest controls and Set callbacks remain owned by the existing Logger.

`movementHeroFocal` owns `focalX`, `focalY`, `scale`, `biasX`, and `biasY` centrally by
stable artwork key. It supplies safe defaults and initial presets for bench, curl, row,
standing curl and Bulgarian split squat compositions. These are **initial, visually
unvalidated presets**, not newly approved artwork. No screen owns ID-based crop exceptions.
Future governed exact accessory families can use the same layer after human approval and
normal exact registry integration; filenames alone cannot add coverage.

The image uses the existing 512px source, memory/disk cache, candidate recycling identity
and a 160ms image transition (zero with reduced motion). Memoized primitive props and stable
layout measurement keep elapsed/rest updates out of image decoding. There is one active
hero rather than a list of image billboards. Moving to a no-art identity unmounts the layer
and restores the compact fallback immediately, with no reserved image region. That boundary
does not currently animate an outgoing image; native transition smoothness remains unverified.
